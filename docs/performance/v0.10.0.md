# Patternia Performance - v0.10.0

**Focus**:
- Automatic matcher caching for stateless case packs
- Transparent performance parity between `on(...)` and `PTN_ON(...)`
- Zero-overhead trait-based dispatch for rvalue pipelines

## Summary

v0.10.0 introduces an auto-cache mechanism for the `on(...)` pipeline. When a case pack consists entirely of stateless patterns and handlers, Patternia now automatically caches the matcher object in a program-wide static slot. This allows the standard `match(x) | on(...)` syntax to reach the performance levels previously reserved for `PTN_ON(...)` or manual caching, without requiring any API changes from the user.

**Performance**: On Apple Clang 17.0.0 (macOS, Release), the 128-literal-case auto-cached path achieves **1.13 ns** per call — a **9.58× speedup** over the non-cached path (10.79 ns). This matches the performance ceiling of `PTN_ON` (1.16 ns) and is within noise of the theoretical optimum (Switch at 1.09 ns).

## Mechanism

The auto-cache operates through a type-keyed magic static inside the rvalue `operator|` overload for `case_pack`. The implementation uses an `if constexpr` gate to dispatch based on the `all_stateless_v` trait:

```cpp
template <typename Subject, typename... Cases>
auto operator|(match_context<Subject>&& ctx, case_pack<Cases...>&& pack) {
  if constexpr (detail::all_stateless_v<Cases...>) {
    static const auto cached = matcher_factory::create(std::move(pack));
    return cached.match(std::move(ctx));
  } else {
    return matcher_factory::create(std::move(pack)).match(std::move(ctx));
  }
}
```

This dispatch ensures that only zero-state matcher objects are cached, preserving the correctness of the match pipeline while eliminating construction overhead on hot paths.

## Trait whitelist policy

Patternia applies a strict effectively-empty policy for auto-caching. The `all_stateless_v<Cases...>` trait is true if and only if every `Case` satisfies:

`(std::is_empty_v<Pattern> || sizeof(Pattern) <= 1) && std::is_empty_v<Handler>`

The `sizeof <= 1` heuristic for patterns accounts for `[[no_unique_address]]`-optimized members. Types like `static_literal_pattern<N>` carry a `[[no_unique_address]] Cmp cmp{}` member where `Cmp` defaults to `std::equal_to<>` (an empty type). While `std::is_empty_v` returns false for such types, they carry zero meaningful state — all instances of `static_literal_pattern<42>` are identical. The `sizeof <= 1` check detects this pattern and correctly classifies them as stateless.

A proposed whitelist for `value_handler<T>` (e.g., `value_handler<int>`) was REJECTED. Because the cache slot is an ODR-merged static inside a member function template, two distinct call sites with identical `Cases...` types would share the same physical storage. If those handlers were allowed to carry state (even trivially copyable state like an `int`), an aliasing hazard would occur where one call site could observe or overwrite the value intended for another. Restricting the cache to truly empty handler types ensures that sharing a slot is always safe.

## Known limitations

- **Constexpr behavior**: The rvalue `operator|` remains `constexpr`. Under constant evaluation, `is_constant_evaluated()` returns true and the cache helper is skipped in favor of the eager path. Existing compile-time benchmarks continue to function unchanged.
- **Toolchain requirements**: On toolchains lacking `is_constant_evaluated` (or a functional equivalent), using the auto-cache path inside a `constexpr` context will result in a hard compiler error due to the function-local static.
- **ODR Merging**: The cache slot is a single program-wide instance per unique `Cases...` type pack. This follows C++17 [basic.def.odr]/6 and the Itanium ABI §5.2.3. Multi-TU safety for this behavior is verified by the test suite.
- **Pre-C++20 Compatibility**: A trait-based shim handles the `is_constant_evaluated` check on older compilers, falling back to `false` when no compiler builtin is available.

## Verification methodology

The implementation passed a triple-verification process:
1. **Runtime Identity**: Verified through `gtest` that cached and non-cached paths produce identical results (T7).
2. **Compile-time Probe**: `static_assert` probes confirmed the correct branch is taken during constant evaluation (T4).
3. **Codegen Golden**: Snapshot comparisons of generated assembly (T10) ensured the function-local static is correctly emitted and keyed by type.
4. **Environment Stress**: ASan and UBSan runs (T9) verified no memory or initialization issues in the static cache.

## Codegen golden refresh

To refresh the codegen golden snapshots after intentional compiler updates or optimizations:

1. Ensure you are on a Linux environment with Clang 18.
2. Run the refresh script: `scripts/refresh_codegen_golden.sh`.
3. Verify the changes in `tests/codegen/lm128_on.s.expected`.

## Rollback plan

If a performance regression or unforeseen stability issue is identified:
- Disable the auto-cache globally by forcing `all_stateless_v` to always return `false`.
- If the breakage is specific to `constexpr` evaluation, revert the `T6.5` shim to its fallback state.
- Both changes are single-point modifications and fully reversible.
