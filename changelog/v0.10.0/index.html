    Patternia v0.10.0 Release Note¶

    Release Date: Unreleased Version: v0.10.0

    Overview¶

    Patternia v0.10.0 introduces implicit auto-caching for match(x) | on(...) when every case in the pack is stateless. Eligible call sites now reuse a per-TU static slot for the case tuple, reaching PTN_ON-class performance without any DSL changes. Stateful packs (those containing user lambdas with captures, runtime lit(value), etc.) keep the existing per-call construction path with byte-for-byte identical behavior.

    Performance highlight: 128-literal-case match | on achieves 1.13 ns per call (Apple Clang 17, Release) — a 9.58× speedup vs baseline (10.79 ns) and within noise of the PTN_ON macro ceiling (1.16 ns).

    New Features¶

    Implicit on() Auto-Cache¶

    int classify(int x) {
  using namespace ptn;
  // Stateless pack (empty patterns + empty handlers) — auto-cached
  // on first call; identical Cases... share one program-wide slot.
  return match(x) | on(
    val<1> >> []{ return 1; },
    val<2> >> []{ return 2; },
    _      >> []{ return 0; }
  );
}

// NOTE: Cases like val<1> >> 1 (non-empty value_handler<int>)
// or lit(runtime_value) are NOT auto-cached — they retain the
// existing per-call construction path with byte-identical behavior.

    Properties:

    • Triggered automatically when every case has empty pattern AND empty handler.
    • Stateful packs (lambda captures, lit(value), val<N> >> int/value_handler<T>, etc.) follow the original per-call construction path — zero behavior change for those.
    • Gated by if constexpr at the rvalue operator| overload only; lvalue match(x) | on(named_pack) is untouched.
    • Constexpr-safe: is_constant_evaluated dispatch falls back to the eager path during constant evaluation, so existing CT benches and static_assert usages keep working.

    Performance¶

    See v0.10.0 performance notes for the full LM128_On regression numbers, methodology, and platform notes.

    Known Limitations¶

    • The rvalue match(x) | on(...) overload REMAINS constexpr. Under constant evaluation, auto-cache is skipped via is_constant_evaluated dispatch — evaluation proceeds via existing eager path.
    • On toolchains without is_constant_evaluated, constexpr usage of match | on with stateless pack will hard-error (function-local static in constant evaluation) instead of silently misbehaving.
    • The lvalue match(x) | on(named_pack) overload retains constexpr (no caching performed).
    • Auto-cache slot is single program-wide for any given Cases... type pack via ODR merging of inline member-function-template statics. Two distinct call sites with identical case types share one slot — this is intentional (zero RAM cost) and verified by multi-TU test.
